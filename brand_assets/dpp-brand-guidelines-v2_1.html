MOTION

Sharp, purposeful animation. Fast in, slightly slower out. One page-load orchestration matters more than a dozen micro-animations. Never animate things that don't need it.

Timing Tokens
--dur-fast
120ms
Button press, icon swap, micro-feedback
--dur-std
220ms
Hover states, border transitions, color fades
--dur-slow
400ms
Card reveals, menu open, panel slides
--dur-xslow
700ms
Page load stagger, hero entrance, scroll reveals
Easing Curves
--ease-out
cubic-bezier(0.16,1,0.3,1)
Primary easing. Fast start, smooth deceleration. Use for elements entering the viewport (slide-in, fade-up).
--ease-std
cubic-bezier(0.4,0,0.2,1)
Standard transitions. Balanced for hover states, background color changes, border animations.
--ease-in
cubic-bezier(0.4,0,1,1)
Exit transitions. Elements leaving the screen. Use sparingly — most exits should just be instant.
Page Load Orchestration
On every page, stagger the entrance of key elements. This creates a feeling of the page "assembling" which reinforces the tech-forward, AI brand. Use animation-delay rather than JS where possible.

// nav_scroll_behavior

NAV SCROLL STATES

The nav has three distinct states. All three must be built — a nav that doesn't respond to scroll feels unfinished.

STATE 1 — AT TOP (scrollY = 0)
→ Background: transparent
→ No border-bottom
→ Height: 68px
→ Hero bleeds through
STATE 2 — SCROLLED (>80px)
→ Background: rgba(4,12,27,0.92)
→ backdrop-filter: blur(12px)
→ border-bottom: 1px solid --navy
→ Height shrinks to: 56px
STATE 3 — SCROLL DOWN → HIDE
→ Scrolling DOWN: translateY(-100%)
→ Scrolling UP: translateY(0)
→ Transition: 300ms ease-out
→ Frees mobile screen space
/* Nav scroll behavior */ .nav { position: fixed; top: 0; left: 0; right: 0; height: 68px; z-index: var(--z-nav); background: transparent; transition: all 300ms var(--ease-out); } .nav.scrolled { height: 56px; background: rgba(4,12,27,0.92); backdrop-filter: blur(12px); border-bottom: 1px solid var(--navy); } .nav.hidden { transform: translateY(-100%); } // Scroll direction detection let lastScroll = 0; window.addEventListener('scroll', () => { const y = window.scrollY; nav.classList.toggle('scrolled', y > 80); nav.classList.toggle('hidden', y > lastScroll && y > 200); lastScroll = y; }, { passive: true });

Requirements
FOCUS RINGS
All interactive elements must have visible focus rings. Use :focus-visible not :focus. Style: 2px solid #0B7EFF, 3px offset.
TAP TARGETS
Minimum 44 × 44px for all interactive elements on mobile. Add padding rather than stretching the element visually.
ARIA LABELS
Icon-only buttons need aria-label. The hamburger menu needs aria-expanded state updates. Logo link needs aria-label="Home".
SEMANTIC HTML
Use <nav>, <main>, <section>, <footer>. One H1 per page. Logical heading hierarchy.
MOTION
Respect prefers-reduced-motion. Wrap all animations in a media query check.
/* Accessibility essentials */ *:focus-visible { outline: 2px solid var(--blue); outline-offset: 3px; } *:focus:not(:focus-visible) { outline: none; } @media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } } /* Skip to content link */ .skip-link { position: absolute; top: -40px; left: 0; background: var(--blue); color: white; padding: 8px 16px; z-index: 999; } .skip-link:focus { top: 0; }

USAGE RULES

The final reference. When in doubt — come back here. These rules protect the brand's integrity across every touchpoint.

Always Do
  • Use Ink (#040c1b) as the dominant background — minimum 60% of any page
  • Reserve Electric Blue for accents only — CTAs, links, stats, the logo node
  • Use Barlow Condensed for ALL headlines at 800 or 900 weight
  • Use :focus-visible for focus rings — 2px solid --blue, 3px offset
  • Honor prefers-reduced-motion with a universal animation disable
  • Use 0–2px border radius on all UI elements — no round bubbles
  • Show skeletons for any content that takes more than 300ms to load
  • Include inline validation on every form field on blur
  • Set a unique title tag and meta description on every page
  • Run Lighthouse before every release — target 90+ performance
  • Use semantic HTML tags: nav, main, section, article, footer, h1-h6
  • Stagger page-load animations using the defined delay system
  • Use 2px stroke line-only icons — Lucide or Phosphor Light
  • Maintain 80–120px section padding on desktop, 40px on mobile
  • Test on iOS Safari and Chrome Android before every release
Never Do
  • Use warm colors (red, orange, yellow, green) as decorative elements
  • Use Electric Blue for body text — it fails contrast on navy backgrounds
  • Add drop shadows, glow effects, or blur on UI components
  • Use gradients beyond subtle navy-to-ink atmospheric backgrounds
  • Remove focus outlines with outline:none without a :focus-visible replacement
  • Animate things that don't communicate state or meaning
  • Leave a form field without all six states designed and implemented
  • Launch without OG images — every page needs one for social sharing
  • Use placeholder text as a substitute for a visible label
  • Let any page go live without a unique title tag
  • Add a third font family — three is the limit (display, body, mono)
  • Use border-radius greater than 4px on any brand component
  • Auto-play video or audio — ever
  • Place the logo on any background other than Ink, Navy Deep, or Off-White
  • Ship a blank or broken empty state — every zero-state needs copy + CTA
